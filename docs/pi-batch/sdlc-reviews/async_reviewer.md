## Core async claims — verified sound

- **Race safety (spec §3, §5)**: fence evaluates on the `FOR UPDATE`-locked row (`events.rs:388-405` returns `created_at`); author-vs-admin boundary race is outcome-partitioned and order-agnostic (F6) — no interleave can produce a half-applied recall. No stale-response vector exists server-side.
- **Gate S1 (async-data §2/§4)**: window check lands *after* the role gate (no window-state info leak to non-privileged actors) and *before* `check_ws_rate_room` in both transports (`frame.rs:163`, `messages.rs:184`) — doomed attempts never burn shared budget. Verified.
- **Retry matrix (async-data §5)**: no auto-retry on any 409 anywhere; the terminal-state WHERE fence + `recalled_at` set-once is the idempotency mechanism (double-submit converges, defect-pattern #2 satisfied server-side); 429 branch precedes the window branch and the two are mutually exclusive per request (preflight 409s before the rate gate).
- **Clock consistency (F5)**: `created_at` is app-clock (`crud.rs:71`), fence compares app-clock `now_utc()` — the DB-clock backdating rejection is correct; `time` is available in `aero-storage` (Cargo.toml:29), so the fence can compile.
- **Metric single emit point (F3)**: preflight is the sole choke point for REST+WS (both handlers verified); role gate precedes the metric, so no false counts from member probes.
- **Parse fallback** matches requirements: `"0"`→ZERO, garbage/negative/overflow→86400, future `created_at`→not expired (negative Duration comparison). No `set_var` in tests (V11) — correct.

## Non-findings (checked, deliberately not flagged)

- **No pending client lock on recall** (defect-pattern #2): acceptable — the tx fence + `recalled_at`-once make double-submit convergent (409 "already recalled" swallowed as success), matching async-data §4's server-idempotency tier; `concurrent_double_recall_has_exactly_one_winner` already pins it.
- **Admin-who-is-also-sender**: predicate `sender_id == actor` applies the window to the author even if they hold owner/admin — this is the requirements' literal rule (§2.3), not a deviation.
- **Repeated window-expired clicks** produce repeated 409+toast with no state change: requirements explicitly non-goal (no UI countdown/hiding); acceptable.
- **Storage-layer line anchors `:265/:267`** drift from actual `:242-246` — the design's own convention says anchors are symbols, and the insertion description is unambiguous; not a finding.

## Verdict

`VERDICT: PASS - The design is async-correct: the window fence runs on the FOR UPDATE-locked row with app-clock consistency, preflight precedes the rate gate in both transports (gate S1), the boundary race is order-agnostic with exactly-one-winner, 409 is never auto-retried, the metric counts each rejection exactly once at the single choke point, and the web branch correctly distinguishes window-expired (surfaced) from already-recalled (convergent). No blocking defects. Findings 1-2 should be folded into the design before implementation (behavioral test for the msg-string discriminator; fix the 19-vs-15 call-site radius), 3-4 are small copy/doc fixes, 5-6 are informational.`
