**Scope reviewed**: `web/recall_errors.js` (new), `web/recall_errors.test.js` (new), the recall wiring in `web/app.js:664-671`, `web/api.js:372-380` (+ `request()` wrapper), `web/render.js:700-812`, `web/ws.js:539` (dormant WS path), cross-checked against server literals (`crates/aero-im-core/src/service/messages.rs:410/498/501/526/561/564/583`, `crates/aero-storage/src/message/authorization.rs:248/251/269`).

## Verified-correct (no action)

- **No debounce on a submit button** — correct per async-data §2 (submit buttons use a lock, never debounce; none applied).
- **No request race on the mutation path** — recall is a single POST; no filter/search/pagination triggers. WS `Edited/Recalled` events are race-protected by the `lastEditAt` order key + resurrect guard (`app.js:306-323`), with a single captured `stamp`.
- **Duplicate-submit outcome is server-safe** — `FOR UPDATE` + terminal fence (`recalled_at IS NULL`) means a second in-flight POST converges to `409 message is already recalled` → `recallErrorToast` → `null` → silent. No double side effect, no double toast.
- **No auto-retry anywhere** (429/409/5xx/network) — matches async-data §5 retry matrix; 429 maps to user guidance ("稍后重试").
- **Lifecycle** — AbortController timer cleared in `finally` (`api.js:65-67`); click handlers GC'd with their nodes; `toast()` is global, so a late `.catch` after node replacement cannot touch unmounted DOM.
- **Data consistency** — single `state.messagesByRoom` source; server payload replaces the entry wholesale; offline edits/recalls converge via `replayChanges` on reconnect (`app.js:333-343`); window copy has no hardcoded duration.
- **Envelope fidelity** — web test mocks the real wire envelope (`conflict: recall window expired`) and it matches the server's thiserror Display; server literals cross-checked and aligned in both test suites.
