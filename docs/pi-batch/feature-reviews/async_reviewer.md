# Async & Data Review — Message Recall (消息撤回)

## What I verified as sound

- **Race prevention is structural, not just loading-boolean**: all mutations funnel through `applyMessageMutation` (app.js:309–321) with a per-message mutation timestamp order key (`lastEditAt`, shared edit+recall) plus a resurrect guard (`arr[idx].deleted_at` → never un-tombstone). Out-of-order NATS redelivery of an old Edited after a newer Recalled is dropped (`ts < prev`).
- **Server-side atomicity backs the client**: `UPDATE … WHERE recalled_at IS NULL AND deleted_at IS NULL` under row-lock + TOCTOU re-check of room role inside the tx (authorization.rs:247–266) makes concurrent double-recall exactly-one-winner; the loser's 409 is mapped to success (end state subsumed).
- **Cursor hygiene fix is correct and tested**: `_lastSeen` now advances only on `type === 'message'` (ws.js:311–316), so a not-yet-fetched create can never be skipped past by a replayed `recalled` frame; regression test added (ws.test.js). Recall frames are deliberately excluded from the delivery-cursor ack path (`_queueDeliveryAck` returns for non-`message`), so no cursor regression.
- **Convergence closed for every ordering**: create-then-recall (in-order replay), recall-before-create (held-branch + backfill rows carry `recalled_at` → `applyChange`), WS-down REST recall (reconnect `replayChanges`, and `changes_since` includes `recalled_at` per query.rs:153–157), reload (server row is authoritative placeholder).
- **No lifecycle leaks, no new timers/listeners, single source of truth** (`messagesByRoom`), server re-validates all permissions (no permission-ui-only).

## Residual risks (acknowledged, non-blocking)

- WS-down + REST recall: stale row until reconnect replay — self-heals, no data divergence (F2 covers the misleading-error half).
- Old-binary rolling-deploy ack-drop of unknown `recalled` frames — documented in plan; deploy ordering discipline required (pre-existing class of risk).

## VERDICT: PASS - No blocking async defects. The dangerous failure modes (duplicate execution, out-of-order clobber, delete-resurrection, stale-response overwrite) are structurally prevented: server-atomic one-shot transition under row locks with TOCTOU re-check, timestamp-ordered client mutation funnel with resurrect guard, in-order durable replay + seq-gate dedup, and a cursor-hygiene fix that is regression-tested. Remaining findings are LOW/MED polish: reactions DOM divergence on mutation replace (F1), REST response discarded + timeout-uncertain messaging when WS is down (F2), missing client submit-lock/idempotency-key with a benign 409 backstop (F3), 401 not routed to reauth (F4), and an untested-but-critical ordering funnel (F5) — all with concrete decision-table-referenced fixes and test recipes.
