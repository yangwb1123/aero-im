Design written to `docs/design/2026-08-06-message-recall-time-window.design.md` (repo design-doc convention: verification ledger + load-bearing facts + sections). Summary of the concrete design:

**Config plumbing** — `AERO_RECALL_WINDOW_SECS` is a plain env, not figment (`AERO__SERVER__*`). Checked the snaplink precedent: `AERO_SNAPLINK_REQUEST_TIMEOUT_SECS` uses `duration_secs(name, default, min, max)` → `integer_env` which **bails fail-loud** (`snaplink_commercial/config.rs:246,486-501`). The requirements pin silent fallback, so the design deliberately diverges: a **pure** `parse_recall_window(Option<&str>) -> time::Duration` (unset/garbage/negative → 86400, `0` → ZERO=unlimited) with a thin env wrapper, read at `ImService::new` mirroring `KeywordModerator::from_env()` (`orig.rs:305`), injected via `with_recall_window` builder — **zero boot change**. Testable without `set_var` (no `serial_test` in the workspace; env mutation is parallel-unsafe — verified).

**Preflight vs tx fence** — same pure predicate `recall_window_expired(created_at, now, window)` (`window ≠ 0 ∧ now − created_at > window`, inclusive boundary: t=window allowed, t=window+1s → 409) at two layers: preflight (author-only via `sender_id == actor`, *before* the workspace rate charge — gate S1) and inside `recall_outboxed_authorized` after the already-recalled check, evaluated against the `FOR UPDATE`-locked snapshot (`events.rs:388-405`). Exact SQL predicate: the row lock and the terminal UPDATE fence `WHERE id AND recalled_at IS NULL AND deleted_at IS NULL` are **both unchanged**; the window is app-level on the locked row. The SQL-alternative (`AND sender_id = $actor OR created_at > now() − $window`) is rejected with three reasons: role is a joined subquery not a column, DB-vs-app clock mixing breaks the inclusive boundary, and the row lock already provides atomicity.

**409 contract** — reuse `Conflict` → HTTP 409 / `{"code":"conflict","msg":"recall window expired"}`; WS error frame automatic (`frame.rs:523`). Precedence pinned last: NotFound → 403 access → 409 deleted → 409 recalled → 403 role → 409 window. Web: today `app.js:667` swallows **all** 409s — new branch discriminates on `err.message` (code stays `"conflict"` per requirements), plus `api.js:374` comment fix.

**Metrics** — new `aero_messages_recall_expired_total`, emitted **only in the preflight** (discovered: it's the single choke point for REST+WS; `recall_message` would count ~zero since the preflight 409s first; storage emits no metrics — verified).

**Tests** — unit (pure parse + boundary, incl. t=window/t=window+1s/0/future); storage DB tests with a key discovery: backdate `created_at` via **app-computed parameter-bound timestamp**, not `now() - interval` (insert uses app clock `crud.rs:71`, fence compares app clock — DB-clock backdating makes the inclusive boundary flaky); admin-override; boundary race partitioned-but-order-agnostic; 15 existing call sites pass `ZERO` (behavior preserved).

**Change radius** — 5 production files (metrics const, messages.rs, orig.rs, authorization.rs, web/app.js+api.js), 3 test files, 3 doc files; **no migration, no route/frame/bus/boot change**.
